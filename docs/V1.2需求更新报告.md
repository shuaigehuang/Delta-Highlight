## 一、新增需求

### 1.1 预览页打开成品文件夹

预览标签页增加「📂 打开文件夹」按钮，在资源管理器中定位成品文件。

- API: `POST /api/open-folder { path }`
- 服务端执行 `explorer /select,<path>`

### 1.2 生成前设置文件名和输出路径

点击「开始自动剪辑」或「重新生成集锦」时，弹出设置对话框：

- 文件名（默认 `highlight-{batch}.mp4`）
- 输出目录（默认 `05-成品/`，支持浏览 `/api/dirs`）
- 兼容模式勾选框（默认不勾选，使用新高效方案）

### 1.3 自动创建工作目录

每次开始工作时，在 `04-剪辑工作区域/` 下自动创建子目录：

```
04-剪辑工作区域/
├── 20260713-20260726_173000/
│   ├── scan-result.json
│   ├── shotlog.json
│   ├── clips/          ← 兼容模式使用
│   └── frames/
```

所有中间文件隔离，便于后续查找。

### 1.4 ffmpeg 单次直出（跳过裁剪中间步骤）

**当前瓶颈**：12 个片段 → 12 次独立 ffmpeg 编码 → 1 次拼接 = 13 次编解码。

**新方案**：利用 ffmpeg concat demuxer 的 `inpoint`/`outpoint`，一次读取源视频、一次编码直出成品：

```
ffconcat version 1.0
file 'C:\素材\video1.mp4'
inpoint 10.5
outpoint 20.3
file 'C:\素材\video2.mp4'
inpoint 5.0
outpoint 15.0
```

```bash
ffmpeg -f concat -safe 0 -i list.txt -c:v libx264 ... output.mp4
```

**前提**：所有源视频相同编码/分辨率/帧率 → DVR 文件均为 3840×2160@60fps H.264，满足。

**性能**：预计提速约 50%（12 片段 ~2-4 分钟 vs 旧方案 ~6-8 分钟）。

**备选**：提供「兼容模式」勾选框，勾选后使用旧的裁剪+拼接方式。

### 1.5 增量编辑成片（已取消）

> 以需求 1.4 的单次直出替代。任何修改后重跑 ffmpeg 直出即可（2-4 分钟），无需实现复杂的中间编辑。

### 1.6 编辑页进度表格

在「镜头编辑」标签页执行「重新生成集锦」时，同步显示处理进度表格（与扫描页相同风格），列出各片段的处理状态。

## 二、技术决策

| 决策 | 说明 |
|------|------|
| ffmpeg 直出 | 使用 concat demuxer + inpoint/outpoint，`-safe 0` 允许绝对路径 |
| 兼容模式 | `clipSegment`（逐个裁剪）+ `concatClips`（拼接），即旧方案 |
| 工作目录 | `{batchName}_{HHmmss}` 格式，唯一性保证 |
| 输出弹窗 | 复用 `/api/dirs` 目录浏览，增加文件名字段 |
