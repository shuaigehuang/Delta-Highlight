## 一、迭代目标

在 V1.0 命令行 Pipeline 基础上，增加**图形化操作界面**和**镜头脚本可视化编辑**功能，降低使用门槛，提升微调效率。

## 二、新增需求

### 2.1 扫描剪辑页面（需求细化）

- 选择目录后，**列出全部素材视频**（表格形式）
- 一键启动全流程，**逐视频展示处理状态**：
  - 扫描状态：pending → scanning → ✅ N次击杀 / ⚠️ 无击杀
  - 裁剪状态：pending → clipping → ✅ 完成 / ⏭ 跳过
- 全局进度条 + 当前步骤提示
- **停止按钮**：随时终止流程
- **已运行时间计时器**
- 完成后显示成品文件信息

### 2.2 加载已有镜头脚本

- 提供独立的镜头脚本加载入口（扫描页 + 编辑页均可触发）
- **shotlog.json 记录素材目录** (`materialDir` 字段)
- 加载时完整校验：
  - `materialDir` 字段存在？不存在 → 提示用户手动选择
  - 素材目录存在？不存在 → 提示"记录的素材目录已不存在，请重新选择"
  - 逐个检查 `sourceFile` 是否在目录中 → 列出缺失文件
- 加载成功 → 跳转编辑页，缺失视频行标记 ⚠️

### 2.3 镜头脚本可视化编辑（需求细化）

- 加载 shotlog，表格形式展示所有片段
- 每个片段附带帧截图（击杀时刻附近）
- 编辑：裁剪起止时间、击杀时刻（增/删/改）
- 编辑后自动校验（clipStart < clipEnd、时间不越界等）
- 保存修改后的 shotlog
- **删除某个镜头**（片段卡片上 🗑 按钮）
- **调整镜头顺序**（↑ ↓ 按钮，影响最终集锦中片段的排列次序）
- 一键重新裁剪 + 拼接

## 三、技术决策

### 3.1 GUI 方案：本地 Web 应用

| 项目 | 选择 |
|------|------|
| 后端 | **Express** (Node.js) |
| 前端 | **Vue 3 CDN**（零 npm 依赖，`<script src="cdn">` 引入） |
| 进度推送 | **SSE** (Server-Sent Events) |
| 启动方式 | `npm start` → 浏览器打开 `http://localhost:3456` |

**选型理由：**
- 零重量级依赖，Express 几 MB
- 可直接 `require()` 复用全部现有 Node.js 模块
- Pipeline 崩溃不影响 Web 服务
- 浏览器原生擅长展示图片 + 表格编辑

### 3.2 Pipeline 执行：server.js 直接编排（架构变更）

> **V1.1 初版**使用 `spawn('node', ['run-pipeline.js'])` 子进程黑盒方式。  
> **细化后**改为 server.js 直接调用各模块，以获得逐视频粒度的进度控制。

```
浏览器 ──SSE── [Express server.js]
                   │
                   ├── ① 视频发现: fs.readdirSync() → videos[]
                   ├── ② 扫描: spawn(PYTHON, [scan_video_only.py, --dir, ...])
                   │        └── 逐行解析 stdout → SSE 推每视频扫描状态
                   ├── ③ 日志: generateShotlog() (同步)
                   ├── ④ 裁剪: 逐个 clipSegment() → SSE 推每片段裁剪状态
                   ├── ⑤ 拼接: concatClips()
                   └── ⑥ 停止: aborted 标志 + activeProcess.kill()
```

### 3.3 server.js 管理状态

| 管理项 | 类型 | 说明 |
|--------|------|------|
| `videos[]` | 数组 | 全部视频，每个含 `{name, path, scanStatus, kills, clipStatus, clipSize}` |
| `scanStatus` | 枚举 | `pending` / `scanning` / `scanned` / `skipped`(无击杀) |
| `clipStatus` | 枚举 | `pending` / `clipping` / `done` / `skipped` |
| `pipelineStep` | 数字 | 当前步骤 1-5 |
| `aborted` | 布尔 | 用户点了停止 |
| `startTime` | 时间戳 | 计时起点 |
| `activeProcess` | 引用 | 当前活跃子进程（用于 kill） |

### 3.4 SSE 事件类型

| 事件 | 数据 | 触发时机 |
|------|------|----------|
| `init` | `{videos: [{name,path}], total}` | 扫描开始，列出全部视频 |
| `video-scan-start` | `{index, name}` | 开始扫描某个视频 |
| `video-scan-done` | `{index, name, kills}` | 某视频扫描完成 |
| `video-clip-start` | `{index, name}` | 开始裁剪某片段 |
| `video-clip-done` | `{index, name, sizeMB}` | 某片段裁剪完成 |
| `video-skip` | `{index, name, reason}` | 某视频跳过（无击杀） |
| `timer` | `{elapsed}` | 每秒推送一次 |
| `step` | `{step, total, message}` | 阶段切换 |
| `done` | `{success, path, sizeMB}` | 全部完成 |
| `error` | `{message}` | 出错或用户停止 |

### 3.5 帧缩略图：按需提取

- 编辑页加载时，对每个片段用 ffmpeg 提取 1 帧
- 时间点：片段第一个击杀时刻
- 分辨率：缩放到 320px 宽
- 存储：`04-剪辑工作区域/frames/`，已提取的缓存复用
- 性能：~1s/片段，12 片段 ≈ 12 秒首次加载

### 3.6 界面布局：三标签页

| 标签页 | 路由 | 功能 |
|--------|------|------|
| **扫描剪辑** | `#scan` | 选目录 → 列出视频表格 → 启动 → 逐视频进度 + 计时 + 停止 → 完成 |
| **镜头编辑** | `#edit` | 加载 shotlog → 截图+表格编辑+删除+排序 → 保存 → 重新生成 |
| **预览** | `#preview` | 播放集锦视频（预留） |

## 四、API 清单

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/events` | GET | SSE 进度推送 |
| `/api/scan` | POST | `{materialDir}` → 启动全流程 |
| `/api/stop` | POST | 停止当前运行的流程 |
| `/api/load-shotlog` | POST | `{shotlogPath, materialDir?}` → 加载并校验 shotlog |
| `/api/set-material-dir` | PUT | `{materialDir}` → 设置/覆盖素材目录 |
| `/api/shotlog` | GET | 获取当前镜头日志 |
| `/api/shotlog` | PUT | 保存编辑后的镜头日志（含校验） |
| `/api/frame` | GET | `?video=&time=` → ffmpeg 提取帧缩略图 |
| `/api/reclip` | POST | 重新裁剪+拼接（跳过 scan） |
| `/api/output` | GET | 获取成品文件信息 |

## 五、加载已有镜头脚本：异常处理链

```
POST /api/load-shotlog { shotlogPath }
  │
  ├─ shotlog.materialDir 缺失? 
  │    → { needMaterialDir: true }
  │    → 前端弹出目录选择器
  │    → PUT /api/set-material-dir → 重试
  │
  ├─ 素材目录不存在?
  │    → { error: "素材目录不存在", path }
  │
  ├─ 素材文件缺失?
  │    → { ok: true, missingVideos: ["xxx.mp4", ...], shotlog }
  │    → 前端标记缺失行 ⚠️
  │
  └─ 全部正常
       → { ok: true, missingVideos: [], shotlog }
```
