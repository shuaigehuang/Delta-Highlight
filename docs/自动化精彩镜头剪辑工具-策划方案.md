# 自动化精彩镜头剪辑工具 — 策划方案

> 创建日期：2026-07-26  
> 状态：原型验证阶段

---

## 一、项目背景

在游戏"三角洲行动"（Delta Force）中录制了大量精彩击杀镜头素材（每段约 30 秒），但人工逐个挑选和剪辑效率极低。游戏在每次击杀时会播放一个独特的音效提示，本项目利用这一特性，通过音频匹配技术自动检测击杀时刻，实现精彩镜头的自动剪辑与拼接。

---

## 二、核心目标

1. **击杀音效检测**：在视频音轨中自动定位击杀音效出现的时间点
2. **精准裁剪**：以检测点为中心，裁剪前 N 秒到后 M 秒的片段
3. **智能合并**：多个击杀间隔较短时自动合并为一个长片段
4. **集锦拼接**：将所有裁剪片段拼接为最终集锦视频
5. **镜头日志**：记录每个击杀时刻，支持人工调整后重新剪辑

## 三、技术方案

### 3.1 核心技术：频域互相关（FFT Cross-Correlation）

```
                          ┌─────────────────────────┐
  击杀音效模板 (WAV) ────→│ 提取 PCM, 转 Mono,       │
                          │ 降采样至 16kHz           │──→ template[]
                          └─────────────────────────┘
                                                          ┌──────┐
                          ┌─────────────────────────┐     │ FFT  │
  视频文件 (MP4) ────────→│ ffmpeg 提取音轨为 PCM,  │     │ 频域 │     ┌──────┐
                          │ 转 Mono, 降采样至 16kHz  │──→  │ 相乘 │────→│ IFFT │──→ 峰值检测
                          └─────────────────────────┘     │      │     └──────┘
                                                          └──────┘
```

**算法流程：**

1. **音频提取**：用 ffmpeg 将视频和模板 WAV 分别导出为原始 PCM（16-bit signed int）
2. **预处理**：转单声道（取左右声道均值），降采样到 16kHz，归一化
3. **频域互相关**：
   - 将信号和反转后的模板分别补零到 2 的幂次（≥ N+M-1）
   - FFT 变换到频域，逐点相乘，IFFT 变换回时域
   - 结果即为互相关序列，峰值位置对应匹配位置
4. **归一化**：除以滑动窗口的能量平方根，得到归一化互相关系数
5. **峰值检测**：找出超过阈值的峰值，按最小间隔过滤（避免同一击杀被重复检测）

### 3.2 技术栈

| 层面 | 技术 | 说明 |
|------|------|------|
| 运行时 | Node.js v24 | CLI 主程序 |
| 视频处理 | ffmpeg 6.0 | 音频提取、视频裁剪、拼接 |
| WAV 解析 | 手动解析 | WAV/PCM 格式简单，无需第三方库 |
| FFT 计算 | `fft.js` | 轻量、高效的 radix-2 FFT 库 |
| CLI 框架 | `commander` | 命令行参数解析 |
| 配置 | JSON | config.json |

### 3.3 性能估算

| 视频时长 | 16kHz 采样点数 | 模板点数 | FFT 尺寸 | 预计耗时 |
|----------|---------------|----------|----------|----------|
| 30 秒 | 480,000 | ~18,000 | 2^19=524,288 | ~2-5 秒 |
| 10 分钟 | 9,600,000 | ~18,000 | 2^24=16,777,216 | ~30-60 秒 |

### 3.4 检测参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `sampleRate` | 16000 | 降采样率（平衡精度和性能） |
| `threshold` | 0.3 | 互相关系数阈值（0~1） |
| `minDistance` | 2.0s | 同一击杀的最小间隔 |
| `beforeSeconds` | 5 | 击杀前裁剪秒数 |
| `afterSeconds` | 2 | 击杀后裁剪秒数 |
| `mergeGap` | 15 | 两个击杀间隔小于此值则合并 |

```

Commands:
  scan   扫描视频，检测击杀时刻，生成镜头日志
```

## 六、风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| 互相关精度不足（击杀音效与游戏中混合声音差异大） | 🔴 高 | 原型验证阶段测试；可通过降低阈值 + 人工复查补充 |
| 性能不达标（长视频处理过慢） | 🟡 中 | 降采样到 8kHz；分段并行处理 |
| 不同地图/模式击杀音效不同 | 🟡 中 | 支持配置多个音效模板，逐一匹配 |
| 4K 视频裁剪/拼接时编码性能差 | 🟢 低 | ffmpeg 硬件加速可用（NVIDIA NVENC） |

## 八、视频辅助检测方案 (新增)

### 8.1 背景

纯音频检测经过多轮验证（波形互相关、频谱模板匹配、多样本共同特征提取），发现一个根本限制：**击杀音效与游戏内其他突发音效（枪声、爆炸）的频谱特征过于相似，无法可靠区分。**

但游戏中有明确的**视觉击杀提示**——击杀发生时屏幕固定位置会出现击杀UI图标（白色/橙色），这是击杀事件的**确定性证据**。结合音频+视频双重验证可大幅提升精度。

### 8.2 击杀UI特征

- **位置**: 3840×2160 屏幕，中心约 (1923, 1482)，搜索区域 1000×100px
- **颜色**: 白色（击杀图标）或橙色（摧毁载具图标）
- **行为**: 出现→停留→漂移消失；连续击杀从左到右排列
- **模板**: 53×62px (白色) / 72×56px (橙色) PNG

### 8.3 技术方案

```
                    音频检测                      视频验证
视频文件 ──→ 提取音轨 ──→ 多样本频谱指纹匹配 ──→ 候选时间戳
                                                     │
              ┌──────────────────────────────────────┘
              ▼
        ffmpeg 提取帧 (候选时间 ±1s, 每0.2s一帧)
              │
              ▼
        Python + OpenCV 模板匹配
        (颜色掩码辅助: 白色HSV / 橙色HSV)
              │
              ▼
        确认/否认击杀 ──→ 最终击杀列表
```

**技术栈**:
| 组件 | 技术 | 用途 |
|------|------|------|
| 帧提取 | ffmpeg | 候选时间附近提取PNG帧 |
| 模板匹配 | Python + OpenCV (`cv2.matchTemplate`) | 在ROI内搜索UI图标 |
| 颜色增强 | OpenCV HSV掩码 | 针对白色/橙色图标优化 |
| 调度 | Node.js `child_process` | 调用Python脚本，整合结果 |

```bash
pip install opencv-python
```
