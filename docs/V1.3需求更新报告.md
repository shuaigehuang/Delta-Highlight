## 一、新增需求

### 1.1 输出清晰度选项（预览模式）

**背景**：剪辑成片时间较长，需要先快速生成一个低画质缩略版本用于筛选镜头，确认后再输出原始画质成品。

在输出设置对话框中增加清晰度选择：

| 选项 | 说明 | 默认 |
|------|------|------|
| 原始画质 | 不改变分辨率，CRF 18 | |
| 360P 预览 | 缩放到 360p，CRF 28，编码更快 | ✅ 默认选中 |

**交互方式**：Radio button 二选一，位于输出设置对话框中"兼容模式"勾选框上方。

**文件名规则**：选择 360P 预览时，自动在文件名后追加 `_preview` 后缀（如 `highlight-20260713-20260726_preview.mp4`），避免覆盖正式版。

### 1.2 目录选择统一为 Windows 原生文件夹对话框

**背景**：当前"浏览..."按钮弹出的是网页内自建的目录浏览弹窗（逐层列目录），体验不如系统原生对话框直观。希望所有需要选择目录的地方，点击后弹出 Windows 原生文件夹选择对话框。

**涉及位置**（共 3 处）：

| 位置 | 当前方式 | 改为 |
|------|----------|------|
| 扫描剪辑页 — 素材目录 | 文本框 + 网页内目录浏览弹窗 | 只读路径显示 + "浏览..."按钮 → 原生对话框 |
| 加载镜头脚本对话框 — 素材目录（needDir/missingDir 时） | 仅文本框，无浏览按钮 | 只读路径显示 + "浏览..."按钮 → 原生对话框 |
| 输出设置对话框 — 输出目录 | 文本框 + 网页内目录浏览弹窗 | 只读路径显示 + "浏览..."按钮 → 原生对话框 |

**保留**：加载镜头脚本对话框中的"拖拽/点击选择文件"（`<input type="file">`）保持不变，因为那是选择**文件**而非目录，且只需要文件内容。

## 二、技术决策

### 2.1 清晰度选项：ffmpeg 缩放参数

| 模式 | ffmpeg 参数 |
|------|-------------|
| 原始画质 | `-c:v libx264 -crf 18 -preset medium`（不变） |
| 360P 预览 | `-c:v libx264 -crf 28 -preset veryfast -vf scale=-2:360` |

- `scale=-2:360`：高度缩到 360px，宽度自动保持比例（`-2` 保证偶数，兼容 H.264）
- CRF 28 + veryfast：大幅加速编码，预览不需要高画质
- 4K→360P 像素量减少约 36 倍，预计编码速度提升 5~10 倍

**传递方式**：前端将 `quality: 'original' | '360p'` 随 `/api/scan` 和 `/api/reclip` 请求发送，后端构建对应的编码参数对象。

### 2.2 原生文件夹对话框：服务端 PowerShell

浏览器 `<input type="file" webkitdirectory>` 无法获取绝对路径（安全限制），而本项目需要绝对路径传给 ffmpeg / Python。

**方案**：服务端通过 PowerShell 调起 Windows 原生 `FolderBrowserDialog`：

```
浏览器点击"浏览..."
  → fetch POST /api/pick-dir { title: "选择素材目录" }
  → server.js spawn PowerShell:
      Add-Type -AssemblyName System.Windows.Forms
      $d = New-Object System.Windows.Forms.FolderBrowserDialog
      $d.Description = "选择素材目录"
      $d.ShowNewFolderButton = $true
      if ($d.ShowDialog() -eq 'OK') { Write-Output $d.SelectedPath }
  → 用户看到 Windows 原生文件夹选择窗口
  → 选择后点确定 → PowerShell stdout 输出绝对路径
  → server.js 返回 { path: "C:\\...\\03-素材\\xxx" }
  → 前端回填路径到对应字段
```

**注意事项**：
- 对话框打开期间 fetch 请求挂起等待（async 不阻塞 UI）
- 用户点"取消"→ PowerShell 无输出 → 返回 `{ path: null }` → 前端不做操作
- 现有 `/api/dirs` 接口和网页内目录浏览器代码保留不删（作为回退），但 UI 上不再作为主入口
